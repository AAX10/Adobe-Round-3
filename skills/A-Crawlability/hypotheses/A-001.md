# A-001 — Crawl-Blocked Important Content

## Mechanism
crawl

## Concrete Claim

IF:
a robots.txt file contains Disallow directives that match URL paths serving important public content (content central to the site's primary purpose and intended for public consumption),

THEN:
a standards-compliant crawler that honors the Robots Exclusion Protocol will not retrieve those URLs, and the affected content cannot enter the crawler's normal discovery and retrieval pipeline.

## Evidence Needed

### To Confirm
- Fetch and parse the site's robots.txt file
- Identify rules applicable to common crawlers (Googlebot, GPTBot, general `*` user-agent)
- Identify a set of important public URLs (from sitemap, navigation, or known content structure)
- Test each important URL against the applicable Disallow rules
- Confirm that the blocked URLs serve genuinely important public content (not admin panels, staging, or internal tooling)
- Verify that the content behind the blocked URL is publicly accessible via direct browser request

### To Reject or Narrow
- The blocked paths are exclusively administrative, staging, internal tooling, or private areas (e.g., `/admin/`, `/wp-admin/`, `/staging/`)
- The blocked paths contain duplicate or low-value content intentionally excluded (e.g., faceted navigation, print versions)
- An Allow directive overrides the Disallow for the specific important URL
- The important content is accessible via an alternate, non-blocked URL

## Observable Signal
One or more important public URLs match a Disallow rule in robots.txt for the relevant user-agent, and no overriding Allow rule exists for those URLs.

## Automated Decision Boundary
A finding is generated when:
1. At least one important public URL is matched by a Disallow rule, AND
2. The Disallow rule applies to a user-agent relevant to crawlers (`*`, `Googlebot`, `GPTBot`, etc.), AND
3. The URL does not match a more specific Allow rule, AND
4. The URL path does not match known administrative/private path patterns (e.g., `/admin`, `/wp-login`, `/api/internal`), AND
5. The URL returns a 200 status code when fetched directly (confirming it serves real content)

## Potential Severity

**Critical**: If a broad Disallow rule blocks an entire content section central to the site's purpose (e.g., `Disallow: /products/` on an e-commerce site).

**High**: If multiple important individual pages are blocked.

**Medium**: If a small number of important pages are blocked.

**Low**: If only supplementary content is affected.

Severity depends on: importance of content, breadth of blocked URLs, whether entire content categories are affected.

## Potential Remediation
Remove or narrow the Disallow directive so that important public content is accessible to crawlers. If the rule was intended to block a subset of pages within the path, use more specific Disallow rules targeting only the non-public paths and add explicit Allow rules for the important content.

## Current Evidence

**SOURCE-DERIVED FACT**: RFC 9309 specifies that a compliant crawler MUST NOT access a URI matched by a Disallow rule for its user-agent group. This is a hard gate — not a suggestion.

**SOURCE-DERIVED FACT**: Google Search Central documentation confirms that Googlebot respects robots.txt Disallow rules and will not crawl blocked URLs, regardless of whether the content is publicly accessible.

**OUR INFERENCE**: If important public content is behind a Disallow rule, it is mechanistically excluded from the crawl pipeline of any standards-compliant crawler.

**UNPROVEN DOWNSTREAM EFFECT**: The direct impact on AI assistant citations is not established by this research. The claim is limited to the crawl pipeline gate.

## Counterexamples

1. **Admin/staging paths blocked** → NOT a finding. Blocking `/admin/`, `/wp-admin/`, `/staging/`, `/internal/` is standard practice and does not affect public content discovery.

2. **Faceted navigation blocked** → NOT a finding. Blocking `/search?`, `/filter/`, or similar parameterized URLs prevents duplicate content crawling and is a recommended practice.

3. **PDF/asset directory blocked but content available in HTML** → NOT a finding if the same information is available on a public, non-blocked HTML page.

4. **Disallow overridden by more specific Allow** → NOT a finding. RFC 9309 specifies that the most specific rule wins; if an Allow rule is more specific, the content is accessible.

5. **Intentionally private content** → NOT a finding. Members-only areas, authenticated portals, or intentionally gated content should be blocked.

## Known Limitations
- Cannot determine the full set of "important" URLs without heuristics or site knowledge
- Importance classification relies on page type signals (navigation links, sitemap priority) which may be imperfect
- Does not account for crawlers that intentionally violate robots.txt
- Does not prove downstream AI citation/ranking impact
- Some sites use meta robots or X-Robots-Tag instead of robots.txt; this check covers only robots.txt

## Experiment Design

1. **Condition tested**: Important public URLs blocked by robots.txt
2. **Expected bad outcome**: Compliant crawlers cannot retrieve the content
3. **Ground truth**: Manual verification that blocked URLs serve important public content
4. **Supports hypothesis**: Important URL returns 200 but matches Disallow rule
5. **Kills hypothesis**: All blocked paths are genuinely administrative/private
6. **Obvious false positives**: Admin paths, staging URLs, faceted navigation
7. **Automatable**: Yes — fully deterministic
8. **Works on unseen site**: Yes — robots.txt is standardized
9. **Evidence emitted**: List of blocked important URLs with applicable rules
