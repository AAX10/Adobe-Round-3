# C-002 — Render-Dependent Structural Metadata

## Mechanism
extract

## Concrete Claim

IF:
relevant structured-data annotations (such as JSON-LD schemas for FAQPage, Product, or other entity types meaningful to the page's content) are injected into the DOM only after client-side JavaScript execution and are absent from the initial HTML response, while the underlying factual text IS present in the initial HTML,

THEN:
a machine reader consuming only the initial HTML will lack the explicit semantic relationships provided by those annotations and must rely on probabilistic text parsing, which reduces extraction precision for structured relationships.

## Evidence Needed

### To Confirm
- Perform a dual-fetch comparison for JSON-LD blocks: raw HTTP GET vs. headless browser render
- Identify JSON-LD schemas present in the rendered DOM but absent from the raw HTML
- Filter for relevant schemas (FAQPage, Product, HowTo, etc.) — ignore generic schemas (WebSite, BreadcrumbList)
- Verify that the meaningful text fields within the render-only schemas ARE present in the raw HTML (confirming this is Semantic Loss, not Information Loss)
- Demonstrate that a machine reader achieves lower structural precision on raw HTML compared to rendered DOM
- Ablation: inject the missing JSON-LD into raw HTML → verify precision restoration

### To Reject or Narrow
- A machine reader achieves equivalent precision on raw HTML via strong semantic HTML alone → structured data was unnecessary for this page
- The render-only schema is generic (WebSite, BreadcrumbList, Organization) or contains no meaningful fields beyond what's in the HTML → no significant semantic gap
- The site intentionally omits JSON-LD and relies entirely on semantic HTML (like Stripe, Amazon) → architectural choice, not a defect
- The site has no JSON-LD in either raw or rendered states → this is a "missing structured data" issue, not a render-dependency issue

## Observable Signal
A relevant JSON-LD schema (FAQPage, Product, etc.) appears in the rendered DOM but is completely absent from the raw HTML payload, while the underlying factual text is present in the raw HTML.

## Automated Decision Boundary
A finding is generated when:
1. A JSON-LD schema appears in the rendered DOM but not in the raw HTML, AND
2. The schema type is relevant to the page type (not WebSite, BreadcrumbList, or tracking/analytics schemas), AND
3. The schema contains meaningful fields (e.g., Question/acceptedAnswer, price, name), AND
4. The textual content of those fields IS present in the raw HTML (confirming Semantic Loss), AND
5. The schema is not duplicated across raw and rendered states

## Potential Severity
**Medium**: Important semantic relationships are render-dependent, but the underlying facts are present in the initial HTML. A capable NLP reader could still extract the facts, but without the explicit structural guarantee.

**Low**: Only supplementary metadata is render-dependent, or no meaningful semantic gap exists.

## Potential Remediation
Server-render the relevant structured-data annotations (JSON-LD `<script type="application/ld+json">` blocks) into the initial HTML response so they are available to machine readers without JavaScript execution.

## Current Evidence

**EXPERIMENTAL OBSERVATION**: Adobe Commerce exhibited this pattern — FAQPage JSON-LD was absent from raw HTML but appeared after rendering. The FAQ text itself was present in the initial HTML.

**EXPERIMENTAL OBSERVATION**: Rivian exhibited this pattern — Product and FAQPage JSON-LD were client-rendered.

**EXPERIMENTAL OBSERVATION** (ablation): Injecting the missing JSON-LD into the raw HTML restored 100% structural extraction precision, proving the gap was caused by the missing schema, not by rendering issues.

**EXPERIMENTAL OBSERVATION** (negative): 19 of 27 tested modern SPAs correctly server-rendered their JSON-LD. The pattern is real but uncommon.

**EXPERIMENTAL OBSERVATION** (counterexample): Stripe, Chase, Amazon, and Figma omit JSON-LD entirely but achieve perfect machine extraction via semantic HTML structure.

**OUR INFERENCE**: Client-rendered JSON-LD creates a semantic availability gap for non-JS readers, but this gap is limited to extraction precision — the underlying facts remain accessible through text parsing.

**UNPROVEN DOWNSTREAM EFFECT**: Direct impact on AI citations/rankings is not established.

## Counterexamples

1. **WebSite/BreadcrumbList JSON-LD appears after rendering** → NOT a meaningful finding. These generic schemas provide minimal semantic value beyond what's in the HTML.

2. **No JSON-LD in either state** → NOT a render-dependency finding. This is a separate "missing structured data" concern, not an H-001B/C-002 issue.

3. **Semantic HTML achieves equivalent extraction** → Reduced severity. If `<dl>`, `<table>`, `<section>` structure makes relationships clear, the JSON-LD gap is less impactful.

4. **Dynamic/tracking JSON-LD** → NOT a finding. Analytics, session, or A/B testing JSON is not semantic content.

5. **JSON-LD duplicated in both states** → NOT a finding. If the schema exists in both raw and rendered HTML, there is no render-dependency.

## Known Limitations
- The pattern is uncommon: only 2 of 27 tested sites exhibited it
- Does not prove that missing JSON-LD reduces AI citations
- Requires page-type classification to determine schema relevance
- Strong counterexamples exist (Stripe, Amazon) proving JSON-LD is not universally necessary
- Limited to JSON-LD; does not cover Microdata or RDFa render-dependency

## Experiment Design

1. **Condition tested**: Relevant JSON-LD absent from raw HTML, present after rendering
2. **Expected bad outcome**: Machine reader loses explicit semantic relationships
3. **Ground truth**: Schema comparison + ablation injection test
4. **Supports hypothesis**: Render-only relevant schema with measurable precision drop
5. **Kills hypothesis**: All relevant schemas are in raw HTML, or HTML structure achieves equivalent precision
6. **Obvious false positives**: Generic schemas, no-JSON-LD sites, tracking schemas
7. **Automatable**: Yes — deterministic
8. **Works on unseen site**: Yes — JSON-LD is standardized
9. **Evidence emitted**: Raw vs rendered schema comparison, field inventory, text verification
