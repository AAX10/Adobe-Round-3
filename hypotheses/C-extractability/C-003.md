# C-003 — Ambiguous Fact-to-Label Association

## Mechanism
extract

## Concrete Claim

IF:
an important factual value (price, weight, duration, capacity, date, or other key attribute) is present in the page's HTML text but is not explicitly associated with a clear label, heading, table header, definition term, or other semantic relationship marker,

THEN:
a machine reader may extract the value but cannot reliably determine what attribute or concept it represents, leading to ambiguous or incorrect fact attribution.

## Evidence Needed

### To Confirm
- Identify important factual values on the page (numbers, dates, measurements, prices)
- Examine the DOM structure around each value to determine its semantic association
- Check for: explicit labels (via `<label>`, `<th>`, `<dt>`, `<caption>`, heading association), ARIA attributes (`aria-label`, `aria-describedby`), table structure, definition lists, or immediately adjacent descriptive text
- Demonstrate that without the visual layout (CSS positioning, columns, spatial proximity), the association between value and concept is ambiguous
- Test extraction: present the raw HTML (or linearized text) to a machine reader and verify whether it correctly associates the value with the right attribute

### To Reject or Narrow
- Semantic HTML clearly associates the label and value (e.g., `<th>Price</th><td>$499</td>`, `<dt>Weight</dt><dd>2.3 kg</dd>`) → NOT ambiguous
- The value appears within a heading or paragraph that provides clear textual context (e.g., "Starting at $499") → NOT ambiguous
- JSON-LD or Microdata explicitly provides the attribute-value mapping → machine-readable association exists
- The value is decorative or supplementary (not a key fact for the page's purpose) → low importance

## Observable Signal
An important factual value exists in page text but its meaning/attribute depends on visual layout (CSS grid/flexbox positioning, column alignment) rather than semantic HTML structure.

## Automated Decision Boundary
A finding is generated when:
1. An important factual value is identified in the page text (numbers matching price/measurement/date patterns), AND
2. The nearest semantic label association cannot be determined from the DOM tree alone (no `<th>`, `<dt>`, `<label>`, heading, or ARIA relationship within the value's DOM ancestry or siblings), AND
3. No JSON-LD or Microdata provides an explicit machine-readable mapping for that value, AND
4. The value is classified as important (relates to the page's core entity — pricing, specifications, availability), AND
5. At least 2 such orphaned values are identified on the same page

## Potential Severity

**Medium**: Multiple important factual values on a page have ambiguous semantic associations, creating a risk of incorrect machine extraction.

**Low**: A small number of supplementary values have ambiguous associations.

Severity depends on: importance of the affected facts, number of orphaned values, whether structured data provides the mapping as fallback.

## Potential Remediation
Associate important factual values with explicit labels using semantic HTML: use `<table>` with `<th>` headers for tabular data, `<dl>`/`<dt>`/`<dd>` for attribute-value pairs, `<label>` elements for form-related values, or ARIA attributes (`aria-label`, `aria-describedby`) for complex layouts. Alternatively, provide explicit JSON-LD or Microdata that maps values to their schema.org properties.

## Current Evidence

**SOURCE-DERIVED FACT**: W3C WCAG Success Criterion 1.3.1 (Info and Relationships) requires that "information, structure, and relationships conveyed through presentation can be programmatically determined." Visual-only associations violate this principle.

**SOURCE-DERIVED FACT**: The HTML specification defines semantic elements (`<table>`, `<dl>`, `<label>`) specifically to encode relationships between labels and values in machine-readable form.

**OUR INFERENCE**: When important facts rely on CSS-based visual positioning for their semantic association (rather than DOM-based semantic markup), a text-oriented machine reader that linearizes the DOM may misattribute or fail to attribute the value.

**UNPROVEN DOWNSTREAM EFFECT**: Direct impact on AI citations is not established. The claim is limited to extraction precision.

## Counterexamples

1. **Semantic HTML clearly links label and value** → NOT a finding. `<th>Weight</th><td>2.3 kg</td>` provides an unambiguous machine-readable association.

2. **Inline prose provides context** → NOT a finding. "The device weighs 2.3 kg and costs $499" has clear textual association even without semantic markup.

3. **JSON-LD provides the mapping** → NOT a finding (or reduced severity). If `"weight": "2.3 kg"` exists in JSON-LD, the machine-readable association is available regardless of HTML structure.

4. **Decorative numbers** → NOT a finding. "Over 10,000 customers served" as a marketing metric does not require precise semantic association.

5. **CSS layout with immediately adjacent text label** → Reduced severity. If `<span class="label">Weight</span><span class="value">2.3 kg</span>` are siblings, DOM proximity provides a reasonable (if imperfect) signal.

## Known Limitations
- Determining whether a value's association is "ambiguous" requires understanding the page layout, which is inherently more complex than presence/absence checks
- Modern LLMs may successfully infer associations from context even without semantic markup, reducing the practical impact
- The check cannot fully replicate human visual interpretation of layout
- Importance classification of specific values requires domain knowledge or heuristics
- The boundary between "adjacent text provides context" and "truly ambiguous" is not always sharp

## Experiment Design

1. **Condition tested**: Important values without clear semantic label association
2. **Expected bad outcome**: Machine reader misattributes or fails to attribute values
3. **Ground truth**: Manual identification of value-label pairs and correct associations
4. **Supports hypothesis**: Machine reader assigns wrong attribute to an important value
5. **Kills hypothesis**: Machine reader correctly associates all values despite lack of semantic markup
6. **Obvious false positives**: Prose with inline context, table-structured data, JSON-LD-mapped values
7. **Automatable**: Partially — value detection is automatable; association analysis requires heuristics
8. **Works on unseen site**: Yes — pattern matching is generic
9. **Evidence emitted**: List of orphaned values with DOM context and association analysis
