# F-002 — Document-Only Critical Information

## Mechanism
lock-in

## Concrete Claim

IF:
critical factual information (specifications, pricing details, service terms, compatibility data, hours, or locations) is available only within a downloadable document (PDF, DOCX, or similar) linked from the webpage, and the webpage itself does not provide an equivalent readable textual representation of those facts,

THEN:
a text-oriented machine reader operating on the webpage's HTML will fail to retrieve those facts from the page itself, because the information exists only within an external binary document.

## Evidence Needed

### To Confirm
- Identify links to downloadable documents (PDF, DOCX, XLSX, etc.) on the page
- Classify the likely content of each document based on link text, surrounding context, and filename
- For documents likely containing important factual information: check whether the same facts appear in the webpage's HTML text
- Verify that the document contains genuinely important facts not available on the page (not a supplementary brochure duplicating page content)
- Demonstrate that a text-only extraction of the page HTML would miss the document-locked facts

### To Reject or Narrow
- The same factual information appears in the webpage's HTML → text equivalent exists; the PDF is supplementary
- The document is purely supplementary (user manual, detailed terms that are not "critical facts") → low importance
- The document link points to a paginated HTML version as well → alternate text path exists
- The page provides a summary/excerpt of the document's key facts in HTML → partial text equivalent

## Observable Signal
A link to a downloadable document (identified by file extension, content-type, or link text patterns like "Download PDF", "Spec Sheet", "Price List") exists on a page, and the page's HTML text does not contain the facts that the document's title/context suggests it contains.

## Automated Decision Boundary
A finding is generated when:
1. A link to a downloadable document is identified (by href extension: `.pdf`, `.docx`, `.xlsx`, or by link text matching document patterns), AND
2. The document link's context (link text, surrounding headings, page type) suggests it contains important factual information (specifications, pricing, service details), AND
3. The webpage's visible HTML text does not contain factual keywords associated with the document's probable content (specification terms, price values, etc.), AND
4. No alternate HTML page link provides the same content

Note: This check does NOT download or parse the document content. It identifies the *gap signal* — a document-link in a factual context with no corresponding page text.

## Potential Severity

**High**: Critical facts (pricing, specifications, compatibility) are available only in downloadable documents with no HTML equivalent.

**Medium**: Important but non-critical facts are document-only.

**Low**: Supplementary information is document-only.

Severity depends on: criticality of locked facts, number of document-only content areas, whether the document content is the primary information source for the page.

## Potential Remediation
Provide an equivalent readable textual representation of critical facts from the document directly on the webpage. Options include: an HTML summary of key specifications, an inline data table replicating the document's factual content, or a structured text section containing the critical information. The document can remain available as a supplementary download.

## Current Evidence

**SOURCE-DERIVED FACT**: Google Search Central can index PDF content, but this indexing is separate from the webpage's own content representation. A machine reader operating on the webpage HTML will not automatically access linked PDF content.

**SOURCE-DERIVED FACT**: W3C accessibility guidelines recommend providing HTML alternatives for PDF documents to ensure content is accessible to assistive technologies.

**SOURCE-DERIVED FACT**: The Round 3 Handbook Section F describes content "carried by something a summarizer can't read" as a cause of information loss — this directly applies to facts locked in downloadable documents.

**OUR INFERENCE**: When a webpage delegates important factual information to a downloadable document without providing an HTML text equivalent, a machine reader consuming the page's HTML will miss those facts. The document may be separately indexed, but the association between the page and the document's specific facts is weakened.

**UNPROVEN DOWNSTREAM EFFECT**: Direct impact on AI citations from document-locked facts is not established.

## Counterexamples

1. **PDF exists but same facts are fully available in HTML** → NOT a finding. The PDF is supplementary; the facts are accessible from the page.

2. **User manual / installation guide PDF** → NOT a finding (unless it contains critical facts like compatibility requirements not on the page). Supplementary documents are expected.

3. **Terms of service PDF** → NOT a finding for most audits. Legal documents are typically supplementary and may intentionally exist only as formal documents.

4. **PDF link with inline HTML summary** → NOT a finding (or reduced severity). If the page says "Key specs: 15.6-inch display, 2.3 kg" and links to a detailed PDF, the critical facts have text equivalents.

5. **Whitepaper / research report** → NOT a finding. Educational content in PDF form is standard and typically supplementary to the page's factual claims.

## Known Limitations
- Cannot verify document content without downloading and parsing it (by design — avoids large downloads)
- Document importance classification relies on context heuristics (link text, filename, surrounding content)
- Some documents may contain only supplementary detail, not critical facts
- Google can separately index PDFs, partially mitigating the lock-in for search
- Cannot determine whether a PDF contains factual data vs. narrative text without inspection

## Experiment Design

1. **Condition tested**: Important facts available only in downloadable documents
2. **Expected bad outcome**: Page-level machine reader cannot extract those facts
3. **Ground truth**: Manual inspection of document content vs. page text
4. **Supports hypothesis**: Document contains critical specs/pricing not on the page
5. **Kills hypothesis**: All document facts are duplicated in page HTML
6. **Obvious false positives**: Supplementary manuals, ToS, whitepapers
7. **Automatable**: Yes — link detection + context analysis
8. **Works on unseen site**: Yes — document link patterns are generic
9. **Evidence emitted**: List of document links with context and HTML coverage analysis
