# H-D1: Entity Graph Connectivity Deficit

**Failure Mode:** Severed `@id` pointers prevent sub-entity aggregation.
**Severity:** Critical / High

## 1. Core Assumption
AI crawlers and knowledge graph constructors (like Google Knowledge Graph or LLM RAG ingestors) map relationships based on explicit object identifiers. They expect a single, canonical `Organization` node where all subsequent entities (Articles, Products, Offers, Reviews) link back via standard schema properties (e.g., `publisher`, `brand`, `author`).

## 2. Technical Failure Mode
The entity graph is flattened or corrupted:
* **Missing Canonical `@id`:** The primary `Organization` object is present but lacks an `@id` URI.
* **Node Collisions:** Distinct entities (e.g., a `Product` and an `Organization`) inadvertently share the exact same `@id`.
* **String-Type Fallbacks:** Child nodes specify `publisher: "BrandName"` as a raw string instead of a structured node reference `{"@id": "https://example.com/#organization"}`.

## 3. Severity & Rationale
* **Critical** if a Node Collision occurs, as this corrupts the AI's internal state.
* **High** if pointers are severed, leading to incomplete entity resolution (the AI knows a product exists, but fails to definitively link it to the parent company).

## 4. Validation Methodology
1. Extract all JSON-LD blobs.
2. Locate the primary `Organization`.
3. Perform an internal graph traversal to ensure `publisher`, `brand`, and `author` properties resolve to the Organization's `@id`.

## 5. Remediation Path
Ensure all JSON-LD blobs injected into the page use absolute, matching URIs for the `@id` key across interconnected components.
