# C-001 — Render-Dependent Factual Content

## Mechanism
read

## Concrete Claim

IF:
important factual information (pricing, specifications, availability, features central to the page's purpose) is populated into the DOM only after client-side JavaScript execution and is completely absent from the initial HTML response,

THEN:
a machine reader that consumes only the initial HTTP response without executing JavaScript will be unable to access or extract those facts, resulting in absolute factual omission.

## Evidence Needed

### To Confirm
- Perform a dual-fetch comparison: raw HTTP GET (no JS) vs. headless browser render (with JS, network idle)
- Identify specific factual text in the rendered DOM that is central to the page's purpose
- Verify that this specific factual text is entirely absent from the raw HTML payload (not in visible text, not in JSON blobs, not in `data-` attributes, not in `<noscript>` tags)
- Demonstrate that a machine reader operating on the raw HTML achieves 0% recall for those specific facts

### To Reject or Narrow
- The factual information is present elsewhere in the raw HTML (e.g., in a `__NEXT_DATA__` JSON blob, `data-` attributes, or `<noscript>` fallback) → a capable parser could extract it
- The missing content is supplementary, decorative, or unrelated to the page's core entity (e.g., "Loading..." text, session state, shopping cart count)
- The site serves pre-rendered content to known bot user-agents (dynamic rendering)

## Observable Signal
Specific, meaningful factual text is present in the rendered DOM but cannot be found anywhere in the raw HTML payload.

## Automated Decision Boundary
A finding is generated when:
1. A factual text string identified in the rendered DOM as important (based on heading association, page type, and content classification) is searched for in the raw HTML, AND
2. The text is completely absent from the raw HTML (no substring match), AND
3. The text is not UI chrome, session data, or decorative content, AND
4. At least one important factual entity meets this criterion

## Potential Severity
**High**: Important factual information itself is unavailable from the initial HTML, creating a hard barrier for non-JS readers.

## Potential Remediation
Server-render critical factual content into the initial HTML payload (via SSR or SSG) so it is accessible to machine readers without JavaScript execution.

## Current Evidence

**EXPERIMENTAL OBSERVATION**: Airbnb listing pages exhibited this pattern — amenity details were absent from the initial HTML and appeared only after JS execution.

**EXPERIMENTAL OBSERVATION**: Zocdoc practitioner pages showed availability information only after rendering.

**EXPERIMENTAL OBSERVATION** (negative): Adobe Commerce and Allbirds correctly server-rendered factual text into the initial HTML despite using JavaScript frameworks.

**OUR INFERENCE**: CSR-only architectures without SSR/SSG can cause factual content to be completely absent from the initial HTML, creating a hard information barrier.

**UNPROVEN DOWNSTREAM EFFECT**: Direct impact on AI assistant citations/rankings is not established by this research. Advanced AI crawlers that render JavaScript would not experience this gap.

## Counterexamples

1. **Rendering changes only navigation/UI chrome** → NOT a finding. If JS adds only interactive navigation, menus, or layout changes but all factual content is in the initial HTML, there is no information loss.

2. **Facts are in `__NEXT_DATA__` JSON within initial HTML** → NOT a finding. Next.js-style hydration data is parseable by capable machine readers even though it requires JSON extraction rather than DOM traversal.

3. **Personalized/session content missing** → NOT a finding. Shopping cart counts, user-specific recommendations, and login state are not "important factual content" for crawl purposes.

4. **Site uses dynamic rendering for bots** → Reduced severity. If the site detects crawler user-agents and serves pre-rendered content, the gap may not affect actual crawlers (though it creates fragility).

## Known Limitations
- Requires an LLM or heuristic to classify what constitutes "important factual content" vs. decorative text
- Cannot detect dynamic rendering (bot-specific pre-rendering) without testing multiple user-agents
- Direct downstream AI citation/ranking impact is not established
- Advanced AI crawlers that render JS will not experience this gap
- Sample size in existing research is limited to specific page types tested

## Experiment Design

1. **Condition tested**: Important facts absent from initial HTML, present after rendering
2. **Expected bad outcome**: Non-JS machine reader cannot extract those facts
3. **Ground truth**: Manual identification of important facts on the rendered page
4. **Supports hypothesis**: Important facts in rendered DOM, absent from raw HTML
5. **Kills hypothesis**: All important facts are in raw HTML (even if layout differs)
6. **Obvious false positives**: UI chrome, session data, navigation changes
7. **Automatable**: Yes — with headless browser + text search
8. **Works on unseen site**: Yes — dual-fetch is generic
9. **Evidence emitted**: List of render-only facts with HTML absence verification
